# ADR-001：确立 ScholarPilot 为唯一主线，其余旁支子系统归档

- 状态：已接受
- 日期：2026-08-05
- 关联：ADR-007（执行路线图 P0）

## 背景

工作区根目录 `AI论文自动化工程/` 下并存了 5 个功能重叠、技术栈各异的子系统：

| 子系统 | 技术栈 | 定位 |
|---|---|---|
| `scholarpilot/` | Python / LangGraph / LiteLLM / MCP / CLI | 现行主线（持续开发） |
| `papertracker_social/` | FastAPI + React/Vite + Celery + PostgreSQL | 上一代 Web 全栈 |
| `papertraker_20260124/` | Flask + cnki_skills + academic_pipeline + `src/`（含 `src/src/` 嵌套复制） | 更早一代，已归档 |
| `papertracker_rich/` | Java Spring Boot + Vue3 + 独立 `literature_fetcher` | 第三份 CNKI 实现 |
| `scholarpilot-demo/`、`scholarpilot-webui-redesign/` | 静态 HTML 原型 | 未来 Web 的候选 UI |

规划文档（`.trae/documents/scholarpilot-implementation-plan.md`）明确这是对"你之前 3 个版本"的**提炼迁移而非搬运**，且不迁移旧 Web 前端、数据库模型、FastAPI 路由。但旧代码在磁盘上**未被隔离归档**，导致 CNKI 采集逻辑被重复实现 3–4 遍、开发时反复出现"改哪一份"的歧义。

## 决策

**确立 `scholarpilot/` 为唯一活动主线，其余 5 个旁支目录全部移入 `_archive/`。**

- `papertracker_social/`、`papertraker_20260124/`、`papertracker_rich/`、`scholarpilot-demo/`、`scholarpilot-webui-redesign/` 移入 `_archive/`，各自保留一份 `README` 说明被取代原因，代码原样保留、不再维护。
- 根目录散落产物（`database_rag.db/.json`、各类 `*_report.json`、`*.catalog.json`、审查报告 md）移入 `scholarpilot/data/archive/`。
- 归档后根目录顶层只保留：`scholarpilot/`、`_archive/`、`参考资料/`。

## 后果

- **正面**：彻底消除"哪个系统在用""改哪份 CNKI"的歧义；仓库边界清晰；后续所有收敛动作有明确落点。
- **负面/成本**：`_archive/` 会占用磁盘；历史代码需要时可手动找回，但不再参与构建与开发。
- **约束**：归档是纯移动+文档动作，**不改任何代码逻辑**，零运行风险。这是所有后续优化的前提（见 ADR-007）。

## 不决策的内容

- 不为归档子系统做迁移/重写；如需能力，从 `scholarpilot/` 新建，而不是复活旧代码。
- 不在归档时删除任何历史实现——保留以便审计与借鉴。

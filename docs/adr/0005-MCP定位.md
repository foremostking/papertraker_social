# ADR-005：MCP 定位为直接导入的引擎包，不做路由层

- 状态：已接受
- 日期：2026-08-05
- 关联：ADR-004、ADR-007（P6）

## 背景

`mcp/` 目录最初被当作"MCP 服务器"来组织，其中 `servers/cnki/`、`servers/wanfang/` 等存放数据源引擎，而 `mcp/client.py` 保留了通过 MCP 协议路由到外部服务器的思路。

实际使用中，这些"引擎"是被 `tools/` 检索管理器**直接以 Python 包形式 import 并实例化**的（如 `CNKIAiohttpEngine`），从未真正走 MCP JSON-RPC 协议。当前架构是"用包的形式实现了引擎，却顶着 MCP 的名义"，造成命名与用途错位。

## 决策

**把 `mcp/servers/` 确立为可直接导入的引擎包（engine package），不构建 MCP 路由层。**

- 明确 `mcp/servers/*` 是进程内直接实例化的检索引擎，与 MCP 协议无关。
- `mcp/client.py` 保留但标记为"未来多进程部署的预留"，不在当前 P0–P5 实现。
- 不新增任何把检索请求转成 MCP 消息再路由回引擎的中间层。

## 后果

- **正面**：消除"伪 MCP"的命名误导；检索链路为直接函数调用，调试直观、性能好；无协议序列化开销。
- **负面/成本**：若将来要跨进程/远程部署引擎，需要把引擎包从 `mcp/` 迁出到真正的独立服务，届时才引入 MCP 客户端；该成本被推迟到真实需要出现时（YAGNI）。
- **依赖**：`tools/` 检索层直接 import 引擎包，与 ADR-004 的合并方向一致。

## 不决策的内容

- 不删除 `mcp/servers/` 目录（避免大范围移动破坏 import），仅重新定义其语义。
- 不实现 MCP 协议服务器/客户端路由（P6 才评估）。

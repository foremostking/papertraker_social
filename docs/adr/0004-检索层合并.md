# ADR-004：检索层合并为单一 LiteratureSearchManager

- 状态：已接受
- 日期：2026-08-05
- 关联：ADR-002、ADR-007（P2）

## 背景

`tools/` 下两个检索管理器职责重叠：

- `tools/search.py` → `LiteratureSearchManager`：多源检索（中文 + WoS + ChinaXiv + PubScholar + OpenAlex + Semantic Scholar + arXiv）。
- `tools/chinese_search.py` → `ChineseLiteratureManager`：仅中文三源（CNKI + 万方 + NCPSSD）。

当前 `LiteratureSearchManager` 在 `__init__` 中构造一个 `ChineseLiteratureManager`，再在 `_search_chinese()` 里委托给它——形成"manager 套 manager"的间接层。该间接层并未带来任何隔离收益（三源引擎本就在同一进程内直接实例化），却增加了跳转与配置传递成本。

## 决策

**合并为单一 `LiteratureSearchManager`，删除 `ChineseLiteratureManager` 类。**

- 将 `ChineseLiteratureManager.search()` 的三源并行检索逻辑下沉为 `LiteratureSearchManager._search_chinese()` 的直接实现（该方法已存在，当前只是委托给另一个 manager）。
- 删除 `chinese_search.py` 中的 `ChineseLiteratureManager` 类，仅保留其数据模型（`ChineseSearchResult`、`UnifiedChinesePaper` 等），供统一结果使用。
- 检索入口收敛为一个类、一份合并去重 + 语义过滤逻辑。

## 后果

- **正面**：单一检索入口与单一编排逻辑；减少一层跳转；职责清晰。
- **负面/成本**：若未来确实需要"仅中文检索"的独立复用场景，需重新拆分——但归档后没有此类调用方，符合 YAGNI。
- **依赖**：依赖 ADR-002（CNKI 已收敛为单一引擎），保证下沉后的逻辑只有一条通路。

## 不决策的内容

- 不合并数据源引擎本身（CNKI/万方/NCPSSD/WoS 等各自保留为独立引擎，见 ADR-005）。
- 不改变各引擎的返回模型接口，仅收敛编排层。
